# GolfVotes

**The golf fixes golfers actually recommend.**

Golf lessons on YouTube, ranked by how often golfers independently recommended them to each other,
sorted by problem: slice, shanks, early extension, chipping and more. Inspired by Karpathy's HackerTube.

## How it works
1. Public comments from golf-instruction communities are scanned for YouTube links.
2. A language model labels each comment: real lesson recommendation or not, which problem, and whether
   the golfer says it fixed it.
3. Each golfer counts once per video. Videos are ranked per problem by these independent recommendations.

This repository contains derived data (video IDs, counts, labels, short summaries) and short excerpts of
public comments that recommend a lesson, each linked to the original. No usernames are published: authors
are not stored, and mentions of other users inside excerpts are masked. The raw data and pipeline live in a
private repository. Want a comment removed? Open an issue with its link.

## Build
```bash
python3 build/build.py   # writes _site/
python3 build/seo_check.py   # indexing gate: sitemap, canonicals, links, titles, orphans
node build/og.js         # optional: regenerates share images in static/og/ (needs Playwright)
```
Deployment: GitHub Actions builds `_site/` and publishes it to GitHub Pages on every push to `main`.

## Indexing
`build/seo_check.py` reads the built pages the way a crawler does and stops the deploy on an error: a sitemap URL
that cannot be indexed, an indexable page that is not listed or that nothing links to, a link that goes through a
redirect, a title used twice. With `--live` it also compares against the sitemap that is online, so that a renamed
path cannot turn hundreds of URLs into 404s unnoticed.

The sitemap is split by kind of page (`sitemap-pages.xml`, `-coaches`, `-lessons`, `-lessons-tail`, `-years`); Search Console
reports indexing per part. Lessons with fewer than three recommendations are the tail. `sitemap-years.xml` lists the year pages `/year/<y>/` (most recommended lessons, coaches and per-problem leaders of a finished year); a year gets a page from March of the following year on if it has at least 1,000 recommendations. `min_recs_indexed` in
`data/site.json` sets from how many recommendations a lesson page asks to be indexed (default: every lesson page).

`build/gsc_report.py` (workflow "Index report", twice a week) asks the Search Console API which sitemap URLs Google
has indexed and commits the answer to `seo/index_report.md`: the indexed share per sitemap part, what changed, and
what needs a fix. It needs the repository secret `GSC_SERVICE_ACCOUNT` (JSON key of a Google service account that is
a user of the Search Console property).

## Structure
- `data/site.json`: name, URLs, newsletter link, thresholds
- `data/problems.json`: problem taxonomy and intro texts
- `data/videos.json`: public, derived video data (generated by the private pipeline)
- `data/years.json`: optional; recommendations per video and calendar year, each golfer counted once per lesson and year (generated by the private pipeline's monthly run); without it no year pages are built
- `data/links.json`: affiliate redirects and ad slots (empty = nothing shown)
- `build/build.py`: static site generator (standard library only)
- `build/seo_check.py`: indexing gate, run before every deploy
- `static/`: CSS, JS, favicon, share images
